---
| 시간 복잡도 | 이름 | N이 100일 때의 대표적인 연산 횟수 | 특징 |
|---|---|---:|---|
| O(1) | 상수 시간 | 1 | 데이터 크기에 영향을 거의 받지 않음 |
| O(N) | 선형 시간 | 100 | 데이터에 비례해 증가 |
| O(N²) | 제곱 시간 | 10,000 | 데이터 개수의 제곱에 비례해 증가 |

- 이진탐색 O(Log N)은 데이터가 커져도 연산량이 상대적으로 천천히 증가한다. 정렬된 배열에서 이진 탐색을 사용하면 탐색 범위를 절반씩 줄여 효율적으로 값을 찾을 수 있다.

```
for (int i = 0; i < N; i++)
{
    CheckMonster(Monsters[i]);

    for (int j = 1; j < N; j *= 2)
    {
        CheckNearbyMonster(i, j);
    }
}
```
- 이 코드는 바깥쪽 반복문은 N번, 안쪽 반복문은 값이 두 배씩 증가하므로 O(Log N)이다.

  => 시간 복잡도는 O(N Log N) 이 된다.
  
- 시간 복잡도가 O(N²)인 코드는 항상 O(N)인 코드보다 나쁜가?

  => 아니다.입력 데이터의 크기와 문제의 특성에 따라 적절한 알고리즘을 골라야 한다. 데이터가 적은 경우에는 O(N²) 알고리즘도 충분히 효율적일 수 있다.
